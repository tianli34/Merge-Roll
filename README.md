# 自动翻页滚动

Windows 小工具：打开网页 → 每页往下滚动固定像素 → 点击“下一页” → 重复 N 页。基于 Python + Playwright + Tkinter。也支持把多页合并成一页后滚到底，或者不翻页、只把当前页滚一遍。

## 快速开始

1. 双击 `安装依赖.bat`（首次会创建 `.venv` 并安装 Playwright，约 1 分钟）
2. 双击 `启动.bat`
3. 填好网址和“下一页”选择器，点“开始”

命令行方式：

```bat
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
```

## 参数说明

| 参数 | 说明 |
| --- | --- |
| 网址 | 起始页面，可省略 `https://` |
| 下一页选择器 | Playwright 选择器。默认 `text=下一页`；也可用 `a[rel=next]`、`li.next a`、`.pagination-next`、`button:has-text('下一页')` |
| 翻页方式 | `点击下一页` = 点按钮翻页；`URL 递增` = 直接把网址里的 `_2`、`_3` 换掉翻页；`合并成一页` = 把各页正文拼到同一页后一次滚到底；`只滚动` = 不翻页，打开这一页就一路滚到底 |
| 浏览页数 | 一共处理多少页（含起始页） |
| 每页滚动(px) | 每页向下滚动的总距离，0 表示只翻页不滚动 |
| 滚动速度(px/秒) | 越小越平滑。500 大约 1 秒滚 1 屏。**运行中也能改**：拖“拖动调速”滑块，或直接改这个数字，滚动下一帧就按新速度走 |
| 翻页后等待(秒) | 点完下一页后额外等多久再开始滚动，页面渲染慢就调大 |
| 滚动方式 | `脚本滚动（平滑·推荐）`（默认）：在页面里按帧推进，60fps 匀速，最稳；`鼠标滚轮（兼容）`：给“只认滚轮事件”的站点留着，按次派发、落地按帧，会有一点点阶梯感 |
| 浏览器 | `msedge`（默认，用系统 Edge，无需额外下载）/ `chrome` / `chromium`（需 `playwright install chromium`） |
| 每页开始前回到顶部 | 按 Home + `scrollTo(0,0)` 复位，避免距离累加 |
| 记住登录状态 | 用 `browser-data/` 目录做持久化用户配置，登录一次后 Cookie 保留；遇到“配置目录被占用”就取消勾选 |

“暂停/继续/停止”会立刻生效：滚动由页面内 `requestAnimationFrame` 逐帧推进，暂停/停止指令在 0.1 秒内下发给页面，暂停时停在当前位置、恢复后继续走完剩余距离，停止则退出并关闭浏览器。运行中拖“拖动调速”滑块可以随时加减速度，日志会写一行“滚动速度改为 N px/s（已生效）”。

## 只滚动（不翻页）

长文章、长图、无限下拉这类“就一页，但很长”的页面，把“翻页方式”选 `只滚动（滚到底）`：

- 打开网址 → 一路滚到底 → 停在底部，**浏览器保持打开**，点“停止”才关
- 不点击任何按钮、不拼接内容、不改写页面 DOM、也不动站点自己的 CSS / JS
- 懒加载的图会随滚动逐步加载；滚到底后如果还有图在下载，会等它们下完再收工
- 无限下拉的页面高度会一直长，最多滚 60 分钟，可用“暂停/停止”随时中断
- 这个模式下“浏览页数”“每页滚动”“下一页选择器”“整组地址直接排一页”都不生效（界面自动置灰），只留“滚动速度”“滚动方式”“浏览器”“记住登录状态”

要是只想滚固定一段距离（不是滚到底），仍旧用 `点击下一页` 模式，把“浏览页数”设成 1、“每页滚动(px)”填距离即可——那种情况程序滚完就关窗口，“只滚动”模式则会留着窗口给你看。

## 跑完之后再看一遍：重新滚动

`合并成一页` 和 `只滚动` 跑到底后不会关浏览器，状态栏会变成“已滚到底 · 窗口保留中”，此时：

- **手动看**：合并页就是一张普通网页，滚轮、PageUp/PageDown、Home/End、拖滚动条都能用
- **让程序再滚一遍**：点工具条上的“重新滚动”——回到顶部，按当前“滚动速度”再滚一次。它**不重新抓取、不重新合并**，所以是秒开；滚完还能再点，次数不限
- 想结束就点“停止”，此时才关浏览器（“开始”一直灰着，因为任务还挂着）

“重新滚动”只在合并 / 只滚动两种模式下可用（其它模式跑完就关窗口，没有可重滚的页面）。

## 和原始示例相比改了哪些地方

- **暂停真的会停**：原版 `time.sleep(0.05)` 在暂停时仍推进状态；现在用 `Event` 分段等待，暂停期间不消耗滚动距离。
- **滚动不再一抖一抖**：从“每 50ms 跳一步滚轮”改成页面内 `requestAnimationFrame` 逐帧匀速推进（细节见“常见问题”里的抖动条目），并新增“拖动调速”滑块，运行中可随时改速度。
- **滚轮能落到页面上**：滚动前把鼠标移到视口中心并 `bring_to_front()`，否则 `mouse.wheel` 可能作用在错误位置或不生效。
- **翻页后确实等到了新页面**：点击后轮询 URL 变化（最多 1.2s）再等 `domcontentloaded`，而不是固定 `sleep(1)`；SPA 站点也不会白等。
- **弹出新标签页不再失效**：检测 `context.pages` 增量，自动切到新页面并关掉旧页面。
- **新增 URL 递增模式**：`/3738.html` → `/3738_2.html`，绕开“找不到或点不到按钮”的站点；并用正文容器空判据识别“超出末页仍返回 200”的空壳页。
- **第 1 页能取全就不翻页**：合并模式先在第 1 页找整组图片地址（base64 隐藏域 / 脚本数组），找到就一次排成一页，81 张图的站点从 1~2 分钟降到 10~25 秒。
- **等图片加载**：滚动前最多等 6 秒让 `<img>` 的 `complete` 全部为真，懒加载/逐张渲染的站点才滚得完整。- **下一页按钮不在视口内也能点**：`locator().first` + `scroll_into_view_if_needed`。
- **滚不动会告诉你**：滚动前后比对 `window.scrollY`，几乎没动就提示改用滚轮或手动拖滚动条。
- **UI 线程安全**：worker 线程通过 `queue` 把日志交给主线程 `after()` 消费，不跨线程碰 Tkinter。
- **配置记忆**：参数存到 `config.json`，下次打开自动恢复。

## URL 递增模式（`_2.html` / `_3.html` 这类站点）

有些站点的分页不是按钮，而是网址后缀：

```
https://www.nnao.cc/Articles/Content/3738.html     第 1 页
https://www.nnao.cc/Articles/Content/3738_2.html   第 2 页
https://www.nnao.cc/Articles/Content/3738_3.html   第 3 页
```

这种站点**不需要点击**，把“翻页方式”改成 `URL 递增（_2 _3 …）` 即可：

- 网址填第一页 `.../3738.html`，程序自动拼出 `_2`、`_3`……
- 也可以直接填 `.../3738_2.html`，那就从第 2 页开始连续往后翻
- 支持补零：`.../3738_02.html` → `.../3738_03.html`
- 不支持带 `?参数` 的地址（这种分页参数含义太杂，请用“点击下一页”）

结束条件按顺序判断：

1. HTTP 404 / 5xx → 停止
2. 页面正文既无文字也无图片 → 停止
3. 常见正文容器（`#pageContainer`、`#content`、`article`、`.post-content` 等）存在但里面是空的 → 停止（用来对付“超出末页仍返回 200”的空壳页）
4. 到达“浏览页数” → 停止

### 以 nnao.cc 这篇文章为例

该站的分页完全由 JS 生成：图片以 base64 存在 `#imgData`，每 4 张一页，页码从 URL 的 `_N` 解析，再把 `3738_2.html` 之类的链接塞进 `#pageNav`。所以：

| 项目 | 值 |
| --- | --- |
| 翻页方式 | URL 递增（_2 _3 …） |
| 网址 | `https://www.nnao.cc/Articles/Content/3738.html` |
| 浏览页数 | 21（81 张图 ÷ 每页 4 张，向上取整） |
| 每页滚动(px) | 3000~4000，按图片高度调 |
| 翻页后等待(秒) | 3（图片是逐张 50ms 渲染出来的，太快会滚不完） |

如果只想用点击方式：选择器填 `#pageNav a:has-text('下一页')`（注意分页条初始是 `display:none`，由 JS 显示，所以要等页面渲染，别把“翻页后等待”设成 0）。

**但这篇其实不用翻页**：81 条地址全在第 1 页的 `#imgData` 里，把“翻页方式”改成 `合并成一页` 一次就能排好（见下一节）。URL 递增/点击方式留着，是给“每页真的只有自己那几张图”的站点用的。

## 合并成一页（图集站点最省事）

“翻页方式”选 `合并成一页`。**翻页、取图片地址、把图片排在同一页是三件事**，所以这里分两条路走：

1. **第 1 页就带着整组地址（快路径，默认开启）**：站点把全部图片地址写在第 1 页的 HTML 里（隐藏域、脚本数组），分页只是前端拿这组地址切片显示。这时**只发一次请求**：解出地址 → 按原顺序拼成一串 `<img>` → 同一个浏览器会话里渲染成一页。不翻页、不下载图片文件、也不拼长图。
2. **每页只有自己的图（旧路径）**：第 1 页里找不到更长的列表，才回退到逐页 `goto` / 点击，抓各页正文再拼成一页。

快路径的判断在 `_collect_whole_image_urls()`：只有“列表明显比本页展示的图更多”才走（本页 4 张、列表 81 张 → 快路径；列表也就 4 张 → 回退，避免把“本页的图”误当成整组）。日志会写明来源和数量：

```
抓取第 1/21 页：https://www.nnao.cc/Articles/Content/3738.html
第 1 页就带着整组图片地址：81 张（来源 #imgData），不必逐页翻，直接排成一页
正在等图片加载（同一浏览器会话内直接引用地址，不下载到本地）…
有 31 张图第一次没取到（站点掐了连接），正在重试第 1 轮…
重试后图片都补齐了
已排成同一页：81/81 张图片，页面高度 63442px，可视区域 1512×982
```

不想要快路径，就把界面上的“整组地址直接排一页”取消勾选（只对合并模式有效）。

设置要点：

| 参数 | 说明 |
| --- | --- |
| 浏览页数 | 旧路径下是抓取上限；快路径下一次取全，这个值不生效 |
| 每页滚动(px) | 合并模式下**不生效**，输入框会自动置灰，改为“滚到底” |
| 滚动速度(px/秒) | 建议 1500~3000，整页高度可能几万像素 |
| 翻页后等待(秒) | 旧路径按 `等待×6`（8~30 秒）等占位图换成真实地址；快路径不需要，保持 1.5 即可 |

### 以 nnao.cc 这篇为例（实测结论）

- 第 1 次 GET `3738.html` 的响应里，隐藏域 `#imgData` 就是 **81 条 base64**，每条解出一条 `/LoadImage.ashx/xxxx.jpg`；`_2.html`、`_3.html` 并不携带新内容——`v3page.js` 只是把这 81 条按 4 张一组切片，页码取自 URL 的 `_N`。**所以这篇一个请求就能取全，不用翻 21 页。**
- 图片只能用 `<img>` 加载（浏览器会话内返回 200，`naturalWidth=600`）。`curl` 和页面里的 `fetch()` 都是 **403**：请求不是图片子资源，被 IIS 直接挡掉。能看、但取不到字节，这就是“不落地文件”的原因。
- 一次挂 81 张时，站点偶尔会掐掉一批连接（表现是一批图 `naturalWidth=0`，并不是没有权限）。换成 `?r=时间戳` 重挂一轮就补齐，日志里会写“重试后图片都补齐了”；两轮还不行才当成坏图从页面移除。
- 81 张加载完约 10~25 秒（同一站点不同时段差异很大），页面高约 63000px，之后按“滚动速度”一路滚到底；滚到底时如果还有图在下载，会等它们下完再收尾。

旧路径（逐页抓正文）仍然保留，流程是：

1. 逐页 `goto`（或点击）取出正文容器的 `innerHTML`
2. **先等图片就位**：正文图片一开始是 `/grey.gif` 的 1×1 占位图，几秒后才逐张换成真实地址；每页都会盯着正文容器，等占位图消失再抓
3. 拼成一份**全新的文档**（`set_content` 重写整页），彻底避开站点自己的 CSS / JS
4. 丢掉残留的 1×1 占位图和确实加载失败的图，左下角显示 `已合并 N 页 · M 张图 · 高度 Xpx`
5. 先把浏览器窗口最大化，再按“滚动速度”一路滚到底；跑完不关浏览器，方便手动回看；点“停止”才关闭

关于“下载成离线 HTML”：图片字节在浏览器外取不到（`curl` / `fetch` 一律 403），要落地只能在会话内逐张转成 data URI 再写文件；目前没做，需要离线留存时在浏览器里“另存为”即可（同源地址仍会失效，另存时选“网页，全部”会连图片一起存）。

## 常见问题

- **滚动时图片一直在“抖”，速度调到 500 尤其明显**：以前是每 50ms 发一次滚轮/`scrollBy`，一步走 `速度×0.05` 像素——500px/s 就是 25px 一步、一秒 20 步。浏览器按帧（60fps）落地，于是三帧里有两帧不动、第三帧猛跳 25px，看图就是持续抖动。实测 500px/s：逐帧位移只有 `{0, 25}` 两种值、67% 的帧位移为 0、速度方差约 640。

  现在默认的 `脚本滚动（平滑·推荐）` 改成页面内 `requestAnimationFrame` 逐帧推进 + `scrollTo({behavior:'instant'})`（无视站点 CSS 的 `scroll-behavior:smooth`，否则两段动画会互相拉扯）。同一页面实测：每帧走 8~9px、**没有静止帧**、速度方差降到 ~28；真站点 81 张图、63442px 的合并页也是同样结果。所以“抖动”跟速度有关系（速度越快，原来那一步跳得越大），但根子在步进方式。

  仍想用滚轮的话，它现在也按时间累计位移（实际速度不再偏慢），但逐次派发天生有阶梯感——实测 500px/s 时仍有 75% 的帧静止、方差 ~870。要平滑就用默认的脚本滚动。

- **拖动调速滑块没反应**：滑块只在“运行中”改写当前任务的速度；没在跑的时候它只是记住这个值，下次“开始”生效。另外暂停状态下也能调，继续后按新速度走。

- **合并后图片不居中、或者看着像被切掉一截**：以前浏览器视口被写死成 1280×860，页面永远按这个尺寸排版——窗口比它宽时右边空一大块（看着偏左、不居中），比它宽的内容会被切在 1280 处，比它矮的屏幕（笔记本 125%/150% 缩放很常见）底部整块看不见。现在改成视口跟随真实窗口，合并模式下还会自动最大化；合并页的图片一律 `width/height:auto` + 左右 `margin:auto`，并且强制冲掉站点写死的高度和 `overflow:hidden` 包裹层，图片只会按原始比例完整显示，不会被裁。
- **合并完成后黑屏、中间只有一条虚线**：站点正文图片一开始是 `/grey.gif` 的 1×1 占位图，几秒后才换成真实地址；旧版本 1.5 秒就抓走了，合并页里只剩一堆 1px 小点。现在会先等占位图换成真图，并把残留占位图丢掉；如果日志里出现“还有 N 张图没换成真实地址”，把“翻页后等待”调大一点
- **Edge 顶部提示“你使用的是不受支持的命令行标志：--no-sandbox”**：Playwright 启动时默认带的参数，与黑屏无关。现在启动时启用 `chromium_sandbox`，这条提示不会再出现
- **双击没反应 / 窗口不出现**：现在启动失败会弹窗并写入 `error.log`，看里面的最后一行即可定位；最常见是配置项取值异常或依赖没装
- **报错 `未安装 Playwright`**：先跑 `安装依赖.bat`，或 `.venv\Scripts\python -m pip install playwright -i https://pypi.tuna.tsinghua.edu.cn/simple`
- **报错找不到浏览器**：Edge 一般都有；否则把浏览器换成 `chromium` 并执行 `.venv\Scripts\python -m playwright install chromium`
- **点不到下一页**：先用浏览器 F12 看按钮的真实结构，把选择器改成更精确的，例如 `#pager >> text=下一页` 或 `a.page-link:has-text('下页')`
- **页面滚动距离明显小于设定**：说明页面到底了或内容在内部滚动容器；改用 `鼠标滚轮（兼容）`，或调大翻页等待时间
- **站点要登录**：勾选“记住登录状态”，第一次运行手动在打开的浏览器里登录，之后会复用 Cookie

## 测试

```bat
.venv\Scripts\python tests\test_logic.py
.venv\Scripts\python tests\test_ui.py
.venv\Scripts\python tests\test_startup.py
.venv\Scripts\python tests\test_merged_layout.py
.venv\Scripts\python tests\test_whole_list.py
```

`test_logic.py` 用模拟的 Playwright 对象覆盖了普通翻页、新标签页、脚本滚动、中途停止、暂停恢复、运行中提速等流程，不需要真实网络。
